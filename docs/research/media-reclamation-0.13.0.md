# Safe automatic media reclamation — 0.13

Implemented automatic cleanup six seconds after the editor opens or switches projects. Only newly persisted sources explicitly tagged `retentionVersion: 1` opt in. Untagged legacy sources remain stored permanently; reading them, opening their projects, registering tab manifests and running a scan never add that tag. This deliberately preserves private undo histories in pre-protocol tabs rather than claiming a migration can enumerate them.

Each current tab keeps a durable union of all possible source IDs it has touched, including pending imports, undo/redo, clipboard history and read-only views. A browser-held Web Lock proves that this manifest is still live; it never expires just because a tab is sleeping or has released editing ownership. Pin transactions run through a shared maintenance gate. Cleanup uses its exclusive form, so it cannot overlap new registration or pin commits. Missing live manifests, unsupported locks and uncertain storage cause cleanup to skip. A failed manifest write holds a separate live veto while ordinary imports and editing remain available.

The collector reads all saved projects, drafts, autosave and legacy template bodies directly, including unindexed records, in the same IndexedDB transaction as deletion. It retains partial source IDs without normalizing them away. A missing indexed project, unreadable root, unfamiliar project version or damaged media record aborts the whole transaction. Active unrecognized ownership tokens also defer cleanup, protecting writers from older application code. A closed modern tab's manifest remains as protocol evidence until its leftover lease expires; its media pins are no longer active and no ownership lease is modified.

An eligible blob must be unreferenced on two observations at least seven days apart, with matching size, MIME type and storage timestamp. Reusing an orphan clears its marker atomically with the new pin. At most 32 blobs and normally 128 MiB are removed per opening; one oversized first blob is allowed so large abandoned videos can eventually be reclaimed. At most 512 new markers are written and scans refuse more than 50,000 keys. Cleanup requires no blob decoding or byte-buffer allocation. Stale manifests and markers are removed when their evidence is no longer needed.

Changes:

- `src/lib/mediaRetention.ts`: shared retention protocol, browser liveness, pins and candidate policy.
- `src/lib/media.ts`: pin before load/decode/import, tag only explicit new storage writes.
- `src/lib/persistence.ts`: atomic conservative collector and pinning before project writes.
- `src/lib/projectOwnership.ts`: publish future tokens and document refs before claiming; existing lease authorization remains authoritative.
- `src/components/editor/hooks.ts`: existing opening cleanup reschedules only when project ID changes.
- `scripts/test-media-retention.mjs`: pure policy and unavailable-lock cases.
- `scripts/test-media-reclamation-browser.mjs`: native shared-origin multi-tab IndexedDB/Web Locks matrix.

Validation: TypeScript, targeted ESLint, existing IO regression and four retention unit tests pass. The existing 14-case ownership browser matrix also passes, including stale-token rejection, opener duplication, takeover flush, reload recovery, independent drafts and closing-owner transfer. Development evidence is saved under `media-reclamation-013-dev/report.json` and `ownership-retention-013-dev/report.json`.

The final development matrix passed all 19 cases with zero page errors, including mixed legacy/new storage, no tag retrofit on load, forced closed-tab lease survival and automatic cleanup after opening another project. Independent code review found no high-confidence race for protocol-aware tabs.

Compatibility scope: untagged pre-existing media is permanently retained. An already-open old application tab can nevertheless read a newly tagged source from a newer saved project without participating in the manifest protocol. Active unknown writers defer cleanup, but an old read-only reader of such new bytes is not enumerable by Web Locks alone. The legacy tag restriction and seven-day grace are conservative migration safeguards, not a claim that historical code can publish live pins. Absolute enumeration of those clients would require an additional origin-wide client inventory or a cross-version migration gate.

Final production validation: reran both native browser suites against the final 0.13 build at `http://127.0.0.1:35362`. `media-reclamation-013-final/report.json` records 19 passing cleanup checks, `passed: true`, and `errors: []`. `ownership-retention-013-final/report.json` records 14 passing ownership checks, `passed: true`, and `errors: []`. Both commands exited 0. The suites use isolated browser contexts with shared-origin native IndexedDB and Web Locks; the grace period is exercised by controlled timestamps rather than waiting seven wall-clock days. Browser coverage here is installed Chromium/Chrome, not a separate Safari/Firefox cleanup matrix.

Final bounded read-only integration review found no high-confidence text-track/retention bug. Independent text overlays contain text style and timing rather than stored media references. Their canvas texture, material and geometry are disposed on unmount in `src/three/CaptionLayer.tsx`; inactive tracks release large rasters, and asynchronous font callbacks unsubscribe or check mount liveness. `src/store/editor.ts` keeps track changes in project undo history, clears stale overlay/position selection on deletion and project replacement, and enforces the existing ownership guard. Full saved/draft/template bodies and live context pin unions remain retention roots even when an overlay changes the visible duration or covers a device. The scoped font preload in `src/export/assets.ts` includes active independent overlays; font loading and generated text canvases do not create media blobs that the collector could remove. This is a code review of these integration paths, not an additional long-running GPU leak test or proof of compatibility with nonparticipating historical clients.
